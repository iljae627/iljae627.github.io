이번 **JBU-CTF**에 박형진, 김민재, 그리고 나 정일재 3명으로 이루어진 **[형진과 재재이야]** 팀으로 출전하여 최종 **장려상**을 수상했다.

전략적으로 특정 분야를 나누어 엄격하게 파고들기보다는, 대회가 진행되는 동안 눈에 보이는 문제들 중 접근할 수 있는 것들을 바로바로 푸는 식으로 임했다. 체계적으로 분야를 분담하지 못한 점은 아쉬움이 남았다.

대회에서 풀어낸 18개 문제에 대한 **핵심 접근 방식**과 **풀이 과정에서 배운 점**, 그리고 특히 기억에 남았던 문제들을 블로그 글로 정리해본다.

## 🔍 가장 재미있었던 문제들 & 깊은 배움

이번 대회에서 포렌식 분야의 **"선물"**과 **"무선침해사고"** 두 문제가 재미있었다[cite: 15, 16].

### 🎁 1. 선물 (Forensics)
사진, 오디오, 동영상, 스크린샷, APK 등 여러 매체에 흩어진 4개의 숫자 조각을 찾아내어 최종 `gift.dat`를 복호화하는 종합 선물 상자 같은 문제였다[cite: 16].

- **어떻게 접근해서 풀었나?**
  1. JPEG 이미지의 `EXIF SubSecTimeOriginal` 태그에서 첫 번째 조각(`720455891026`)을 발견했다[cite: 16].
  2. 오디오(`wish_0333.wav`)와 수정한 동영상 오디오 스트림의 BFSK 신호를 복조해 두 번째, 세 번째 조각(`331744820913`, `043166208541`)을 복원했다[cite: 16].
  3. 스크린샷 이미지의 LSB(최하위 비트) 비트스트림을 추출한 후 XOR 연산으로 네 번째 조각(`558930174266`)을 확보했다[cite: 16].
  4. APK 파일의 DEX 상수를 분석하여 PBKDF2-HMAC-SHA256(100,000회) 및 AES-GCM 복호화 메커니즘과 조작 순서를 파악해 최종 플래그 레코드를 완성했다[cite: 16].

- **무엇을 배울 수 있었나?**
  단순히 하나의 아티팩트만 보는 것이 아니라, **다양한 멀티미디어 채널에 숨겨진 힌트들을 연계하고 조합하는 사고력**을 키울 수 있었다[cite: 16]. 또한 APK 역분석을 통해 암호화 알고리즘의 파라미터와 키 생성 로직을 정밀하게 추출하는 기법의 중요성을 깊이 체감했다[cite: 16].

### 📡 2. 무선침해사고 (Forensics)
SCP 카페의 와이파이 환경을 모사한 802.11 무선 패킷 캡처 파일(`scp_cafe_capture.pcap`)을 분석하는 침해사고 대응 문제였다[cite: 15].

- **어떻게 접근해서 풀었나?**
  1. RSSI 신호 세기와 TSF 타임스탬프의 차이를 비교하여 정상 AP(`60:29:d5:83:e7:04`)와 공격자의 Rogue AP(`06:25:9c:3a:1f:b7`)를 구별해내고, 공격자의 Deauth 공격 흐름을 포착했다[cite: 15].
  2. 평문 HTTP 메모에서 와이파이 패스워드 규칙 힌트를 찾아내어 WPA2 Handshake MIC를 오프라인으로 사전 공격(Crack)하여 비밀번호(`scpcafe_4817`)를 확보했다[cite: 15].
  3. 해당 키로 무선 패킷을 복호화하여 HTTP 요청 내 첫 번째 플래그 조각을 얻고[cite: 15], EAPOL M3 과정에서 추출한 GTK(Group Temporal Key)로 브로드캐스트 패킷(CCMP Key Index 1)을 복호화해 두 번째 플래그 조각을 얻어 결합했다[cite: 15].

- **무엇을 배울 수 있었나?**
  **무선 네트워크 침해사고 대응(IR)의 프로세스**를 그대로 경험해볼 수 있었다[cite: 15]. 패킷 복호화 단계를 넘어, Unicast 통신 외에도 Broadcast/Multicast 패킷 분석을 위해 GTK를 활용해야 한다는 점을 확실히 배우는 계기가 되었다[cite: 15].

### 🔑 Cryptography (암호학)

1. **Bing Bong**
   - **접근 방식**: AES-128 암호화 로직 중 특정 조건에서 S-box가 생략되는 구현 결함을 파악하고, 동일 평문에 대한 반복 암호문 통계 분석을 통해 생략된 라운드를 식별했다[cite: 2]. $S(F[i] \oplus K[i]) = C[i] \oplus K[i]$ 관계식을 기반으로 10라운드 키를 복원한 뒤 AES 키 스케줄을 역산해 마스터 키를 찾아냈다[cite: 2].
   - **배운 점**: 암호 알고리즘 자체의 결함뿐만 아니라, **구현상 발생하는 Side-Channel 형태의 Fault Injection 결함**을 통계적 역산으로 공략하는 기법을 배웠다[cite: 2].

2. **Resident Records**
   - **접근 방식**: 255개 CSV 파일에 적용된 Feistel 구조에서 라운드 함수가 재사용된다는 점을 파악했다[cite: 3]. `no`와 `participant_id` 필드의 0라운드 입력이 동일하다는 성질을 이용해, ASCII 문자 범위에 대한 순환 상관 점수(Circular Correlation)를 도출하여 문자를 복원했다[cite: 3].
   - **배운 점**: **대칭형 블록 암호나 Feistel 구조에서 라운드 키/함수 재사용이 발생할 때 생기는 치명적인 통계적 취약점**을 수학적으로 공략하는 감각을 익혔다[cite: 3].

3. **ssiiggnn**
   - **접근 방식**: Winternitz One-Time Signature(W-OTS)의 Forward Hashing 특성을 이용했다[cite: 4]. $secret$ 메시지에 대한 직접 서명 요청은 막혀 있었지만, 두 개의 임의 메시지 $m_1, m_2$에 대한 서명을 조합하고 체크섬 조건($q_{11} \le s_{11}, q_{12} \le s_{12}$)을 충족시켜 $secret$의 서명을 위조해냈다[cite: 4].
   - **배운 점**: **양자 내성 암호 기반인 OTS(일회용 서명) 구조의 작동 원리**와, 여러 서명 조각의 해시 체인 관계를 이용해 원하는 서명을 유도해내는 위조 공격 메커니즘을 이해할 수 있었다[cite: 4].

### ⚙️ Reverse Engineering (리버싱)

4. **License Manager v2.0**
   - **접근 방식**: 해시 연산 후 `0x00ffffff` MASK 때문에 정상 검증 비교가 불가능한 의도된 버그를 파악했다[cite: 5]. 분기문 opcode를 패치(`0x74 JE` $\rightarrow$ `0x75 JNE`)한 뒤, 패치된 영역의 SHA-256 디코딩 키 스트림을 정적으로 생성하여 hidden payload를 복호화했다[cite: 5].
   - **배운 점**: 단순 바이너리 패치에 그치지 않고, **패치된 바이너리 코드 자체가 다음 단계의 복호화 키로 사용되는 Self-validating 구조**를 분석하고 정적으로 재현해내는 테크닉을 배웠다[cite: 5].

5. **Split Gate**
   - **접근 방식**: `/proc/self/exe`를 다시 열어 컨테이너 데이터를 직접 파싱하는 구조를 역분석했다[cite: 6]. 1단계 RSA 연산식을 인수분해로 역산해 티켓을 얻고[cite: 6], 2단계 40비트 소수 $p$ 환경의 이산로그 문제를 BSGS(Baby-Step Giant-Step) 알고리즘으로 해결하여 플래그를 출력시켰다[cite: 6].
   - **배운 점**: 바이너리가 자기 자신을 파싱해 내부 구조체를 복호화하는 기법과, **리버싱 문제 속에 결합된 정수론 문제(RSA, 이산로그)를 알고리즘으로 빠르게 풀어내는 방법**을 익혔다[cite: 6].

6. **Tetris**
   - **접근 방식**: 테트리스 게임 바이너리를 분석하여, 블록 고정 출처가 중력 타이머(Gravity)인지 Soft Drop(아래 방향키)인지에 따라 32비트 은닉 상태 머신 비트가 업데이트됨을 알아냈다[cite: 7]. 목표 상태(`0x69691905`)에 도달하기 위한 16개 블록의 조작 비트열을 전수 조사 역산했다[cite: 7].
   - **배운 점**: 단순 화면상의 게임 결과가 아닌 **내부 이벤트 호출 경로(Call Stack)의 차이가 상태 머신의 변수로 작용하는 로직 리버싱**의 재미를 느꼈다[cite: 7].

### 🛡️ System Hacking / Pwnable (시스템 해킹)

7. **GHOST**
   - **접근 방식**: `printf("%s", buf)`의 NUL 바이트 덮어쓰기 누출 특성으로 스택 카나리를 leak했다[cite: 8]. 이후 ret2libc 체인으로 `read@got`를 출력하여 libc base를 계산한 후 `system("/bin/sh")` ROP 체인을 실행했다[cite: 8].
   - **배운 점**: 카나리의 첫 번째 NUL 바이트만 정교하게 덮어 카나리 전체 값을 노출시키는 **가장 정석적이면서도 깔끔한 Canary Leak 기법**을 재확인했다[cite: 8].

8. **Magic Guard**
   - **접근 방식**: 스택 오버플로우 시 입력 앞부분 8바이트가 PNG 시그니처(`\x89PNG\r\n\x1a\n`) 검증을 거치는 것을 확인했다[cite: 9]. 오프셋에 맞게 패딩을 채운 후 리턴 주소를 `flag()` 함수로 교체하여 해결했다[cite: 9].
   - **배운 점**: 버퍼 오버플로우 공격 시 **프로그램 내에 존재하는 특수 시그니처나 포맷 검증 조건을 우회하도록 페이로드를 정렬하는 기법**을 연습할 수 있었다[cite: 9].

9. **JBUMON**
   - **접근 방식**: 게임 저장/불러오기(Save/Load) 수행 시 `skill_count`가 누적 가산되어 최대 슬롯 수(6개)를 초과하는 로직 버그를 발굴했다[cite: 10]. 활성화된 4, 5번 숨겨진 슬롯에서 Canary와 `puts` 주소를 Leak한 후 ROP 체인으로 셸을 획득했다[cite: 10].
   - **배운 점**: 단순 메모리 오버플로우 외에도 **상태(State) 관리 버그를 활용해 정상적인 접근이 불가능했던 스택 메모리 영역의 값을 Leak하고 활용하는 복합적인 익스플로잇**을 익혔다[cite: 10].

10. **숨은 그림 찾기 좋아하세요**
    - **접근 방식**: 조회 메뉴의 음수 인덱스 검증 누락(OOB Read)을 이용해 스택 상단에 픽셀 형태로 회전/인코딩된 네 개의 주소 문자열을 읽고 복호화하여 PIE/libc base 및 ROP 가젯을 구했다[cite: 11]. 이후 OOB Write를 통해 RIP 위치에 `system("/bin/sh")` ROP 체인을 작성했다[cite: 11].
    - **배운 점**: **스택 상의 데이터 구조를 역산하여 ASLR을 우회하는 과정**과, 배열 범위 검사 누락이 가져오는 강력한 익스플로잇 가능성을 체감했다[cite: 11].

11. **피노키오의 코를 원래대로 되돌리자**
    - **접근 방식**: 메모리 풀 할당자(Allocator)의 free 청크 병합 시, 전역 free 횟수의 홀수 Parity에서 청크 크기를 잘못 계산하는 로직 버그(Coalescing Bug)를 이용했다[cite: 12]. 인접 청크를 침범하는 Overlapping Chunk를 만든 뒤, 함수 콜백 포인터의 하위 2바이트를 `win()` 함수 주소로 오버라이드했다[cite: 12].
    - **배운 점**: **커스텀 메모리 할당자(Custom Allocator)에 존재하는 로직 버그를 이용해 Overlapping Chunk를 생성하고, 2바이트 부분 덮어쓰기(Partial Overwrite)로 PIE를 우회하는 고급 힙/메모리 익스플로잇 기법**을 배웠다[cite: 12].

### 🌐 Web (웹 해킹)

12. **서점에 어서오세요**
    - **접근 방식**: 장바구니 수량 변경 API(`POST /api/cart/update`)에서 음수 수량을 허용하는 검증 누락으로 잔액을 대폭 올렸다[cite: 13]. 이후 권한 부족으로 결제 실패 시에도 `orderId`가 미리 생성되는 취약점과, 주문 확정 API(`GET /order/confirm`)가 미결제 주문 건의 권한/결제 상태를 재검증하지 않는 IDOR 취약점을 결합해 미결제 도서를 강제 수령하여 읽어냈다[cite: 13].
    - **배운 점**: **비즈니스 로직상의 검증 부재(음수 수량, 결제 상태 재검증 누락)가 어떻게 체인화되어 심각한 결제 우회 취약점으로 이어지는지** 실무적인 관점에서 배울 수 있었다[cite: 13].

### 🕵️ Forensics (디지털 포렌식)

13. **절대실수를하지마**
    - **접근 방식**: Vim의 영구 실행 취소 파일(`.note.txt.un~`) 구조를 분석했다[cite: 14]. 원본 `note.txt`에서는 내용이 삭제되고 덮어써졌지만, 실행 취소 레코드(Undo Log) 바이너리 내에 이전 수정 내역이 그대로 남아있는 점을 이용해 `strings`와 `grep`으로 플래그를 추출했다[cite: 14].
    - **배운 점**: **에디터나 시스템이 자동으로 생성하는 백업/히스토리 파일(Undo File)에 중요한 비공개 데이터나 이전 작업 내역이 노출될 수 있다는 포렌식적 관점**을 배웠다[cite: 14].

14. **Are you an analyst**
    - **접근 방식**: Ubuntu 커널 메모리 덤프(`memory.raw`)를 다루었다[cite: 17]. 단순 Volatility 명령어 플러그인 출력에 의존하지 않고, QEMU 코어 파일의 페이지 테이블을 직접 워킹(Page Table Walking)하여 은닉 커널 모듈(`inode_index`)이 `mariadbd`, `nginx`, `php-fpm8.2` 프로세스 스택에 나누어 은닉해둔 64바이트 레코드를 수집 후 xorshift로 복호화했다[cite: 17].
    - **배운 점**: **Volatility 프로파일 미스매치가 발생하는 특수 환경에서 수동으로 페이지 테이블을 추적하여 가상 주소를 파일 오프셋으로 변환하고, 메모리 상의 숨겨진 구조체를 복원하는 하드코어 포렌식 기법**을 습득했다[cite: 17].

15. **테이큰**
    - **접근 방식**: Windows 메모리 덤프 분석 중 악성 Bun 프로세스(PID 3540)를 추적했다[cite: 18]. 메모리 상의 C2 경로와 토큰을 매칭하고, Registry 셀에서 복원한 `MachineGuid` 및 `ComputerName` 정보를 추출하여 AES-256-CBC 키를 도출했다[cite: 18]. 최종적으로 `TKN2` 구조로 쪼개져 메모리에 남아있던 클립보드 탈취 데이터를 복호화해냈다[cite: 18].
    - **배운 점**: **악성코드 분석과 윈도우 메모리 포렌식을 결합하여, 시스템 고유 정보(MachineGuid)와 프로토콜 콤포넌트를 이용해 메모리 내 암호화된 C2/클립보드 유출 데이터를 복원하는 고급 침해사고 분석 프로세스**를 배웠다[cite: 18].

16. **Start**
    - **접근 방식**: 문제에서 제공된 안내 파일 내 텍스트 문자열을 직접 열람하여 정답 형태를 확인하고 제출했다[cite: 1].
    - **배운 점**: CTF의 시작 단계로서 플래그 제출 형식과 인코딩 정합성을 점검하는 기초적인 절차를 확인했다[cite: 1].

## 💡 느낀 점 & 마무리

이번 JBU-CTF는 암호학, 리버싱, 시스템 해킹, 웹, 포렌식 전 영역의 문제들이 있던 대회였다.

비록 사전에 분야를 명확히 나누고 정밀한 전략을 세워 임하지는 못했지만, **[형진과 재재이야]** 팀원들과 실시간으로 풀이를 교환하고 해결해 나가며 **장려상**이라는 뜻깊은 성과를 거둘 수 있었다.

다양한 문제들을 풀며 나의 기술적 한계를 테스트해보고, 특히 깊이 있는 포렌식/시스템 문제들을 파헤치며 문제 해결 능력을 한 단계 성장시킬 수 있었던 소중한 시간이었다. 이번 대회에서 얻은 배움을 바탕으로, 다음 대회에서는 더욱 철저한 준비와 역할 분담을 통해 한 단계 더 높은 성적에 도전해보고 싶다.
