## 1. voice-in-the-packet

### Challenge Overview
* **Category:** Forensics
* **Description:** 20초 분량의 VoIP 통신 패킷(G.711 µ-law 오디오 RTP 패킷 1,000개) 분석 문제

### Notes & Analysis
Wireshark에서 수많은 오디오 패킷이 쏟아져 초반에는 정답 데이터의 위치를 파악하는 데 어려움이 있었습니다.

* **바이너리 차이점 비교:** `scapy`로 RTP 페이로드를 추출해 패킷을 비교했는데, 995개 패킷은 완전히 동일하고 전반부 5개 패킷의 짝수 오프셋 데이터만 `0x01` 차이가 난다는 점을 포착했습니다.
* **LSB 스테가노그래피 복기:** 오디오 샘플의 LSB에 데이터를 숨기는 표준적인 스테가노그래피 방식임을 파악하고, 비트들을 MSB-first로 결합 후 디코딩하여 플래그를 도출하는 흐름을 배울 수 있었습니다.

```python
# RTP 페이로드 LSB 비트 추출 및 복원 흐름
bits = [str(payload[idx] & 1) for payload in non_template_payloads for idx in range(0, len(payload), 2)]
raw_bytes = bytes(int("".join(bits[i:i+8]), 2) for i in range(0, len(bits), 8))
```

## 2. check-the-fine-print

### Challenge Overview
* **Category:** Forensics
* **Description:** PNG 파일 내부에 248개의 소형 PNG(19x9) 파일이 묶인 ZIP 파일이 첨부된 문제

### Notes & Analysis
일반적인 이미지 픽셀 툴(`zsteg` 등)로는 데이터가 나오지 않아 픽셀 분석에 주력하다 막혔던 문제였습니다.

* **포맷 명세 확인:** 픽셀이 아닌 PNG 헤더 명세로 눈을 돌려, 각 소형 PNG 파일의 26번째 바이트(`IHDR` Compression Method)를 확인하는 과정을 거쳐야했습니다.
* **비정상 헤더 값 감지:** PNG 표준상 `0`이어야 하는 압축 값이 일부 파일에서 `1`로 설정된 이상 현상을 발견하고, 248개 파일에서 1비트씩 수집(31바이트)하여 텍스트를 복원하는 접근법을 관찰했습니다.

```python
import glob

# IHDR compression method(26번째 바이트) LSB 추출 흐름
bits = [open(f, "rb").read()[26] & 1 for f in sorted(glob.glob("*.png"))]
flag = bytes(int("".join(map(str, bits[i:i+8])), 2) for i in range(0, len(bits), 8))
```

## 3. unfinished-file

### Challenge Overview
* **Category:** Forensics
* **Description:** Chrome 미완성 다운로드 파일(`.crdownload`) 분석 문제

### Notes & Analysis
Chrome 전용 `CRDL` 헤더로 시작하며 중앙 디렉토리가 손상된 구조였습니다.

* **로컬 파일 헤더 탐색:** 팀원이 헥스 에디터(HxD)로 파일 내부를 탐색하며 로컬 파일 헤더 시그니처(`PK\x03\x04`)를 추적, `hidden/.flagdata` (47바이트) 영역을 파싱해 내는 방식을 확인했습니다.
* **XOR 연산 맥락 이해:** 덤프한 바이너리가 단일 바이트 XOR 처리되어 있음을 확인하고, Known Plaintext 인 `t` (`0x74`)와 첫 바이트 `0x36`을 연산하여 Key(`0x42`)를 구하고 데이터 전체를 복호화하는 과정을 보조했습니다.

```python
# PK\x03\x04 헤더 추적 후 47바이트 덤프 및 Single-byte XOR 복호화
key = payload[0] ^ ord('t')  # 0x36 ^ 0x74 = 0x42
flag = bytes([b ^ key for b in payload])
```

## 4. thomas-schools-of-china

### Challenge Overview
* **Category:** Forensics
* **Description:** 오리 그림이 들어있는 커스텀 `.tsc` 이미지 컨테이너 파일 분석 문제

### Notes & Analysis
* **커스텀 구조 파싱:** 헤더(Magic, Version, Width, Height 등 17바이트) 뒤에 RGBA 픽셀 데이터가 나열된 구조였습니다.
* **채널 차이 필터링:** 단색 몸통 픽셀 제외 기준($\max(R,G,B) - \min(R,G,B) < 5$)을 세우고, 채널 간 차이가 크게 나는 반점 픽셀들의 RGB 값을 ASCII로 직렬화하여 데이터를 구성하였습니다.

## 5. invisible-ink

### Challenge Overview
* **Category:** Forensics
* **Description:** PDF와 ZIP이 결합된 Polyglot 파일 분석 문제

### Notes & Analysis
* **폴리글롯 파싱:** 파일 헤더(`%PDF-`)와 트레일러(ZIP EOCD)를 이용해 텍스트 레이어에서 비밀번호를 추출하는 단계를 지켜보았습니다.
* **이미지 왜곡 역연산:** 압축 해제 후 나온 왜곡 이미지(`original_distorted.png`)에 `skimage.transform.swirl`을 음수 strength(-8.5) 값으로 적용해 왜곡을 풀어내는 과정을 관찰했습니다.

## 6. loud-packets

### Challenge Overview
* **Category:** Forensics
* **Description:** 애니메이션 캐릭터 스프라이트 패턴 기반 비트맵 폰트 이미지 문제

### Notes & Analysis
* **패킷 문제라는 이름의 트릭:** PCAP 파일이 존재하지 않고 대형 이미지(`chall.png`)가 제공된 문제였습니다.
* **다운샘플링 역발상:** 각 글자가 약 $80 \times 80$ 타일 크기의 캐릭터 비트맵으로 구성된 점을 이용해, Nearest-Neighbor 방식으로 이미지를 $1/80$로 축소한 뒤 문자를 아스키 아트로 그려내는 독특한 해결법을 지켜보았습니다.

```python
from PIL import Image

# 80x80 타일 축소 후 아스키 아트로 출력
im = Image.open("chall.png")
small = im.resize((im.width // 80, im.height // 80), Image.NEAREST)
```
